# 모둠 동작 영상 만들기

## 수업 흐름

1. 첫 화면의 **교사용 설정**(`/teacher-settings.html`)에서 기존 4자리 비밀번호로 들어갑니다. 기존 API·이미지 설정과 체험 운영 설정을 같은 메뉴에서 열 수 있습니다.
2. 수업 이름으로 수업방을 개설하고, 생성된 6자리 수업코드를 안내합니다.
3. 학생은 `/group-motion.html`에서 수업코드와 1~6모둠을 선택합니다. 입장한 모둠의 녹화만 조회하고 저장합니다.
4. 왼쪽 아바타와 오른쪽 내 모습을 보면서 카메라를 켜고 움직여 봅니다. **녹화 → 일시정지 / 녹화 이어하기 → 녹화 끝내기 → 내 녹화 확인하기**로 진행합니다.
5. 녹화는 최대 60초이며 일시정지 시간은 제외됩니다. 기본은 아바타만 저장하며, 필요하면 **아바타 + 내 모습**을 선택합니다. 소리는 녹음하지 않습니다.
6. 끝내기를 누르면 우리 모둠 서버 보관함에 저장합니다. 다른 기기에서도 같은 수업코드·모둠으로 입장하면 확인할 수 있습니다. 교사는 수업방의 1~6모둠 버튼으로 각각 확인합니다.
7. 수업방을 종료하면 학생의 새 입장·저장·조회가 차단됩니다. 교사는 기존 녹화를 확인하거나 수업방을 다시 열 수 있습니다.

## 저장과 접근

- `fashion-rooms` Edge Function이 PIN 확인, 수업방 생성, 모둠 입장, 녹화 업로드·조회를 담당합니다. 기존 `ai-fashion-api`와 공통 API 키는 유지합니다.
- 8시간 세션 토큰에는 역할·수업방·모둠이 서명됩니다. 학생 요청의 다른 roomId/group 값으로 접근 범위를 바꿀 수 없습니다. 수업코드를 아는 학생이 입장 화면에서 자신의 모둠을 선택하는 수업용 구조이며 개인 계정 인증은 아닙니다.
- 표·비공개 `fashion-group-clips` 저장소는 브라우저 직접 조회를 허용하지 않습니다. 서버가 해당 모둠의 영상에만 10분 재생 URL을 발급합니다. 오래 열어 둔 재생창은 새로고침하면 갱신됩니다.
- 업로드는 최대 50MB, 60초로 제한하며 준비된 파일의 용량·형식을 확인한 뒤 목록에 표시합니다.
- 업로드 실패 시 초안은 기기의 IndexedDB에 수업방·모둠별로 분리해 보관합니다. **다시 저장 / 기기에 저장**할 수 있습니다. 기기 저장소를 사용할 수 없으면 탭을 닫기 전에 저장해야 합니다.
- 이전 버전의 기기별 4명 녹화 데이터는 삭제하지 않지만 새 수업방에 자동 공유하지 않습니다.
- 교사 PIN은 서버 해시 확인과 시도 횟수 제한을 적용합니다. 기존 키오스크의 PIN과 동일한 공유 교사용 코드이며 개인 교사 계정을 대체하지 않습니다.

- 실제 서버에서 수업방 개설, 모둠 입장, 합성 영상 업로드·재생, 교사 조회와 다른 모둠 차단을 확인합니다.

## 승인 디자인 기반 아바타 v3

- `assets/kids/approved/boy-front.png`, `girl-front.png`: 사용자가 선택한 디자인을 바탕으로 GPT 이미지 생성으로 만든 모델링 참고 이미지.
- `assets/kids/boy.glb`, `girl.glb`: 참고 이미지를 Hunyuan 3D v3.1 Pro로 입체화하고 Meshy 몸 관절을 받아 Blender에서 보정한 실제 모델. 노란 티셔츠 남학생과 라벤더 티셔츠 여학생.
- 각 모델은 몸 관절 24개와 직접 추가한 손가락 관절 30개, 총 54개 관절을 포함합니다. 기존 자동 리깅 결과에는 손가락 관절이 없었습니다.
- 여학생 생성 모델의 붙은 손가락은 다섯 손가락이 있는 남학생 손 메시를 손목에 맞춰 연결했습니다. 얼굴·머리·의상·몸통 디자인은 유지했습니다.
- `tools/repair-generated-hands.py`: 여학생 손 메시 교체와 닫힌 손목 연결.
- `tools/prepare-generated-avatar.py`: 손가락 관절 추가, UV 경계 중복 정점 용접, 자동 스킨 가중치, 정규 T포즈 변환, 2048px 텍스처와 GLB 내보내기.
- `assets/kids/approved/*-finger-landmarks.json`: 실제 메시를 보고 맞춘 손가락 위치.
- `/avatar-design-review.html`: 참고 이미지와 실제 3D 모델 비교. 팔·손가락, 앉기 시범과 정면·측면·뒷면 보기.
- `kid-rig.js`가 GLB의 기본 자세를 VRM 형태의 회전 관절로 변환하고 부모 회전을 고려합니다.
- `motion.js`는 이 아바타에 3D 포즈 좌표, 어깨·골반 회전, 가려진 다리 유지, 앉기 높이를 적용합니다. 얼굴 표정 인식은 요청하지 않습니다.
- 예전 `tools/build-kid-avatars.py`는 이전 시제품의 생성 스크립트이며 v3 모델의 생성기로 사용하지 않습니다.

## 확인 범위와 한계

- 실제 GLB의 팔 들기에서 머리 메시가 끌려가지 않는지, 각 손가락 관절과 스킨 가중치가 있는지, 검지를 굽힐 때 다른 손가락이 독립적으로 유지되는지 자동 검사합니다.
- 합성 MediaPipe 포즈·손·체형 좌표로 측면 회전과 앉기 전달을 검사합니다. 이 검사는 실제 카메라 정확도를 증명하지 않습니다.
- Blender에서 정면·팔 들기·측면 앉기·손 근접 동작을 렌더링해 메시 변형을 점검했습니다. 손목의 미세한 재질 이음과 큰 팔 동작의 옷 주름은 남을 수 있습니다.
- 카메라 없는 시범 동작은 실제 추적과 구분되며 녹화 영상에도 **시범 동작**으로 표시합니다.
- 실제 카메라에서는 몸 뒤로 가려지는 손·팔·다리, 빠른 발차기와 손가락 인식이 흔들릴 수 있습니다. 학교 기기에서 실사용 확인이 필요합니다.
- 화면의 정면·측면·뒷면은 아바타를 바라보는 시점이며 촬영 카메라 여러 대를 뜻하지 않습니다.
- 앉기 높이는 다리 자세에서 추정합니다. 의자 충돌, 정확한 바닥 접지, 줄넘기 줄과 도구는 구현하지 않습니다.
- 정면에서 체형을 처음 한 번 보정하고 촬영 거리가 크게 바뀌면 다시 맞춥니다. 줌은 카메라가 지원할 때만 표시합니다.

검사: `npm test` (Node 22.15 이상).
